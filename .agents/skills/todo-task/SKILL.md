# todo-task

진행 상황의 기준은 프로젝트 보드(이슈)다. `docs/tasks.md`는 계획이고 체크박스 · 담당은 봇이 보드를 따라 갱신한다. 이 순서를 따른다.

## 1. 최신 상태와 사용자 확인

1. `git pull --rebase`로 최신 `docs/tasks.md`를 받는다.
2. 사용자가 누구인지 확인한다: `gh api user -q .login` 또는 `git config user.name`.

|---|---|

| hyeongrae-kim | 김형래 |
| baejun10 | 배준범 |
| baekyutae | 배규태 |

모르면 사용자에게 이름을 묻는다.

## 2. 내 작업 보여 주기

1. 내 이슈를 가져온다(진행 상황의 기준): `gh issue list --assignee <로그인> --state open --json number,title,body`
2. 각 이슈 본문의 남은 할 일(`- [ ]`)과 **선행**(본문 "관계"의 이슈 번호)을 읽는다. 선행 이슈가 닫혀 있으면 선행이 끝난 것이다.
3. 작업 설명(어디에 필요 · 만들 것 · 완료 기준)은 `docs/tasks.md`의 `### [T번호]` 섹션에서 읽는다.
4. 표로 보여 준다: 작업 · 이슈 · 우선순위 · 남은 할 일 수 · 선행이 끝났는지.
5. 인자로 작업 번호(예: `T3`)를 받았으면 그 작업으로 바로 간다. 아니면 **P0이고 선행이 끝난 작업** 중 첫 번째를 추천하고 확인받는다.

## 3. 작업하기

0. `main`은 보호돼 있어 직접 push할 수 없다. `main`에서 브랜치를 만든다: `git switch -c t<번호>-<짧은-이름>` (예: `t3-onprem-k3d`).
1. 고른 작업의 **어디에 필요 · 만들 것 · 목표 · 완료 기준**과 관련 설계 문서 절(`docs/plan.html`)을 읽고 시작한다.
2. 남은 할 일을 위에서부터 하나씩 한다. 한 번에 하나.
3. 다른 사람 작업 영역(다른 담당의 파일이나 할 일)을 바꿔야 하면 멈추고 사용자에게 알린다.

## 4. PR 올리기

1. 코드 변경을 커밋한다. 메시지 앞에 작업 번호: `[T3] k3d 클러스터 생성 스크립트 추가`
2. 계획이 바뀌었으면(할 일 문장 수정 · 추가 · 다른 작업으로 이동) 같은 PR에서 `docs/tasks.md`의 그 작업 섹션을 고친다. **체크박스는 고치지 않는다.**
3. 이슈 번호는 `gh issue list --search "[T3]" --state all`로 찾는다. PR 본문에 `Refs #번호`, 할 일이 다 끝나고 **완료 기준**을 만족하면 `Closes #번호`.
4. 사용자에게 확인받은 뒤 브랜치를 push하고 PR을 연다: `gh pr create --title "[T3] …" --body "…"`.
5. 자동 머지를 건다: `gh pr merge --auto --squash`. CI(`terraform` · `charts` · `iac-scan`)가 실패하면 고쳐서 같은 브랜치에 다시 push한다.

## 5. 이슈에서 체크하기

1. PR이 머지되면(`gh pr view <번호> --json state -q .state`가 `MERGED`) 끝낸 할 일을 **이슈에서** 체크한다:
   `python3 scripts/sync_tasks.py tick T3 <할 일 순번>` (순번은 1부터, 이슈 본문의 할 일 순서). 아직 머지 전이면 사용자에게 머지 후 체크하라고 알린다.
2. 그다음은 자동이다(`sync-tasks` 워크플로):
   - 체크가 생기면 보드 **In progress**, 전부 체크되면 이슈가 닫히고 **Done**
   - `docs/tasks.md`의 체크박스 · 담당이 봇 PR로 갱신된다
   - 보드가 움직이면 Slack으로 알린다
3. 담당을 바꿔야 하면 이슈 Assignees를 바꾼다(tasks.md가 따라간다).

## 하지 않는 것

- 체크만 하고 실제 작업이나 검증을 건너뛰지 않는다. 완료 기준을 확인하지 못했으면 그렇게 말한다.
- `docs/plan.html`에 진행 상황을 적지 않는다(설계 문서다).
- 작업 번호(T번호)를 바꾸거나 다시 쓰지 않는다.
- 다른 사람 작업의 할 일을 체크하지 않는다.
- `docs/tasks.md`의 체크박스와 담당을 직접 고치지 않는다(봇이 보드를 따라 고친다).
