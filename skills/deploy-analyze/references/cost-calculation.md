# 월 비용 계산과 예산 비교 (T16 / C5)

calculate는 입력과 저장된 단가로 월 비용을 계산한다. 네트워크 요청, 새 가격 추정, 자동 환율 조회와 자원 변경은 하지 않는다. 금액은 Decimal로 계산하고 십진 문자열로 저장한다. 계산 중 정밀도는 80자리이며 표시용 반올림은 보고서에서 수행한다.

## 실행과 산출물

```sh
python <skill-dir>/scripts/price.py calculate \
  --input <app-root>/.deploy/analysis/pricing-input.json \
  --prices <app-root>/.deploy/analysis/prices.json \
  --assessment <app-root>/.deploy/analysis/resource-assessment.json \
  --output <app-root>/.deploy/analysis/costs.json
```

assessment는 C4 map으로 생성한 입력을 계산할 때 함께 전달한다. 수동으로 작성한 입력은 생략할 수 있다. 입력·단가·평가 결과의 ID, 대상·리전·항목 집합과 해시를 확인한다. 오래된 입력에 대한 단가나 평가 결과는 거부한다. 단위·구간·통화·GCP 원본 Money와 정규화 단가의 일치도 검사한다. 출력은 어떤 입력과 단가로 계산했는지 각각의 해시를 기록한다.

종료 코드는 완전한 계산 0, 미산정 항목이 있는 부분 결과 3, 계약·연결 오류 2, 파일·내부 오류 1이다. 예산 초과나 예산·환율 미정 자체는 실행 실패가 아니다. 출력이 입력·단가·평가 파일을 덮어쓸 수 없으며, 오류 시 기존 결과를 성공한 새 결과처럼 보고하지 않는다.

결과 형식은 [가격 계약](price-format.md)의 costs.json 버전 3다. C6에서 이 파일을 분석 보고서에 연결한다.

## 월 비용의 계산 기준

- 시간 요금: 단가 × 같은 규격 자원 개수 × 명시 시간. 상시 기본 입력은 월 730시간이다. 시연 시간은 별도 입력 시나리오로 작성한다.
- 저장소: 단가 × 자원 개수 × 자원 하나의 GB-month 또는 GiB-month 사용량이다. 여기에 730을 다시 곱하지 않는다.
- 요청·송신·로그: 실제 입력한 사용량과 단가·구간으로 계산한다. 예상 사용자 수만으로 바이트나 로그량을 자동으로 만들어 넣지 않는다.
- 같은 공급자 서비스·SKU·정규화 단위의 사용량은 한 번 합친 뒤 구간 요금을 적용한다. 같은 SKU에 가격 근거나 고정/변동 분류가 서로 다르면 입력 오류다.

예를 들어 첫 10GB는 1달러, 이후는 0.5달러이며 두 항목이 각각 6GB와 8GB를 사용하면 총 14GB에 한 번 과금한다. 합계는 12달러이며 두 항목에 첫 구간을 각각 적용한 14달러가 아니다.

항목별 비용은 입력 순서대로 추가되는 사용량의 차액으로 배분한다. 이 배분은 자원별 실제 청구서라는 뜻이 아니다. 사용량이 범위면 항목별 최솟값·최댓값의 발생 조건이 다를 수 있으므로 항목 범위의 합과 전체 범위가 같지 않을 수 있다. 전체 금액은 summary를 사용하며 보고서가 항목 범위를 다시 더해 합계를 만들지 않는다.

## 구간 집계와 기존 사용량

GCP aggregationInfo가 일 단위이거나 여러 기간을 묶으면 월 합계만으로 구간 요금을 계산하지 않는다. unsupported_aggregation으로 미산정 처리한다.

ACCOUNT 또는 PROJECT 범위의 월 구간 요금은 이번 구성 밖에 있는 기존 사용량을 알아야 한다. 항목 attributes의 tier_baseline_usage에 같은 정규화 단위의 십진 문자열로 명시한다. 이 값은 가격 API 상품 필터가 아니며 조회기는 이를 필터로 전달하지 않는다. 같은 SKU의 기준값이 서로 다르면 오류다.

기준 사용량 B와 이번 구성 사용량 U에 대한 요금 함수가 F라면 비용은 F(B+U) − F(B)다. 계정/프로젝트 집계인데 B를 제공하지 않으면 unknown_aggregation_baseline으로 남긴다. 일반적인 단일 단가에는 구간 집계 기준이 비용을 바꾸지 않는다. 무료 구간·크레딧의 자격을 자동으로 가정하지 않으며 GCP 유료 단가의 원본 근거를 유지한다.

버전 3 v2beta 결과는 무료 구간을 포함한 원본 가격표도 보존한다. 무료 구간을 계산하려면 같은 SKU의 모든 항목에 free_tier_policy=verified_catalog와 명시적인 tier_baseline_usage가 필요하다. 자격·공유 범위·기존 사용량을 확인하지 않았다면 unverified_free_tier로 비용을 미산정 처리한다. API 조회 성공은 월 비용을 계산할 정보가 모두 있다는 뜻이 아니다.

secret_month는 시크릿 또는 활성 버전·복제 위치의 월 사용량, metric_month는 커스텀 메트릭의 월 사용량, sample은 Prometheus 샘플 수다. 각각의 단가에 명시 사용량을 곱하며 GB나 요청 수로 바꾸지 않는다. Public NAT의 VM별 시간, 로그의 추가 보존량, 로드밸런서의 송·수신 처리량도 서로 구분해 입력한다.

## 전체와 앱 추가 증분

전체 사용량은 앱을 추가한 뒤의 구성이고 증분 사용량은 추가된 양이다. 전체 사용량 T, 추가 사용량 I, 별도 기준 B라면 증분 비용은 F(B+T) − F(B+T−I)다. 증분량에 첫 구간 요금을 다시 적용하지 않는다.

단일 단가는 증분량에 직접 곱할 수 있다. 구간 요금은 전체량이나 증분량 중 하나가 고정된 경우에 범위를 계산한다. 둘 다 범위이고 서로의 관계를 알 수 없으면 증분을 미산정으로 남긴다. replicas 감소를 노드 감소로 간주하거나 근거 없는 절감률을 적용하지 않는다.

fixed_usd와 variable_usd는 입력의 고정/변동 분류로 구분한다. known_total_usd와 known_incremental_usd는 알려진 비용 소계다. total_complete와 incremental_complete로 각 비교 범위의 완전 여부를 확인한다. 단가·사용량을 모르면 항목은 null이고, 상한이 없으면 max는 null이다. 모든 비용이 미조회면 소계를 0으로 만들지 않는다.

## 환율과 예산 판정

환율은 입력의 usd_to_krw, 기준일과 출처를 사용하고 결과 assumptions에도 남긴다. 환율이 없으면 USD 결과는 보존하고 KRW 합계와 예산 판정은 미정이다. 완전한 비용 범위만 total_krw 또는 incremental_krw로 환산하며 부분 소계를 전체 합계처럼 표시하지 않는다.

기본 비교 범위는 전체 비용이다. 사용자가 범위를 명시한 경우에만 budget_basis=incremental을 사용한다. T15의 KRW 예산 범위를 그대로 보존하며 예산 null이나 max:null을 0원 또는 무제한으로 해석하지 않는다.

- over: 환산 가능한 알려진 비용 하한이 예산 상한보다 크다. 추가 비용이 미정이어도 이미 초과가 증명되면 이 상태다.
- within: 비교 범위가 완전하고 환율·예산 상한이 있으며 비용 상한이 예산 상한 이하다.
- may_exceed: 완전한 비용 범위가 예산 상한을 가로지른다.
- unknown: 예산·상한·환율·비용 또는 매핑 조건이 부족해 판단하지 못한다.

C4 assessment에 카탈로그·용량·운영 비용 등의 미정 조건이 남아 있으면 예산 충족을 확정하지 않는다. 전체 비용이 알려졌지만 증분만 미정인 경우, 전체 기준 판정에는 증분 미정을 적용하지 않는다.

온프레미스의 빈 클라우드 항목은 클라우드 비용 0이다. 전기·장비·인건비는 C4 assessment의 별도 값이며 이 USD 계산기에 합산하지 않는다. 따라서 이 결과만으로 온프레미스 전체 운영 예산을 충족한다고 판단하지 않는다. 보고서에는 클라우드 비용과 별도 운영 비용을 구분해야 한다.

## 대안 견적 비교

```sh
python <skill-dir>/scripts/price.py compare \
  --baseline <baseline-costs.json> \
  --alternative <alternative-costs.json> \
  --output <savings.json>
```

대안은 별도의 자원 구성·사용량 입력과 그 입력에 맞는 단가로 calculate를 실행해 만든다. changed input에 기존 단가 파일의 해시를 임의로 바꿔 실조회 결과처럼 사용하지 않는다. 후보 ID 집합과 비교 범위가 같은 두 결과를 비교한다.

savings.json의 schema_version은 "1"이다. baseline_sha256, alternative_sha256, generated_at, status, candidates, issues를 기록한다. 후보별 candidate_id, basis, currency=USD, status, monthly_savings 범위와 reason을 기록한다. 절감 범위는 기준 하한−대안 상한, 기준 상한−대안 하한이다. 음수는 대안이 더 비쌀 수 있다는 뜻이다.

비교 범위가 미산정이면 monthly_savings는 null이고 unknown_savings를 남긴다. 금액은 두 자원 견적의 차이일 뿐 적용·성능·가용성 검증이 아니며, 환율 차이나 미산정 온프레미스 운영 비용으로 절감액을 만들지 않는다. 노드 구성과 사용량이 같으면 노드 절감액은 0이다.

## 확인 범위

자동 테스트는 합성 단가를 사용해 시간·저장소·수량·공유 SKU·구간·증분·환율·예산 경계·부분 실패·대안 차액과 파일 보존을 확인한다. 입력·단가·평가 해시 불일치와 GCP 원본 단가 변조도 거부한다. 실제 API 단가 기반 demo-app 보고서 검증은 C7에 남아 있다.
