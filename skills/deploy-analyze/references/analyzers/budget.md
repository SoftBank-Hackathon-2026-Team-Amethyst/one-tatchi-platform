# 예산 분석기

후보 배포 대상마다 예상 월 비용을 내고 브리프의 예산 범위와 비교한다.

## 조사할 것

- **예산.** 브리프의 `monthly_budget`(원화 범위). `max: null`은 상한 미정이지 무제한이 아니다. `null`이면 예산 없이 추정하고 가정에 적는다.
- **비용 항목.** AWS: EKS 컨트롤 플레인, 노드(`t3.medium` × 2), NAT 게이트웨이 1개, ALB, RDS(`db.t4g.micro`), ECR 저장, 로그 · 지표, 아웃바운드 트래픽. 온프레미스: 클러스터가 이미 있다고 보고 클라우드 비용 0, 대신 운영 부담(전원 · 네트워크 · 사람)을 따로 적는다. GCP: 구현체(T4) 전까지는 참고 비교만.
- **공유 인프라.** 팀 공용 클러스터(EKS `one-tatchi`)에 test · prod 네임스페이스를 올리는 구조라, 앱 하나를 더 올릴 때의 **증분 비용**(이미지 저장, 파드 자원, DB)과 **전체 비용**을 나눠 적는다.

트래픽 분석기의 추천 크기가 필요하다. 병렬로 돌아 그 결과가 아직 없으면 기본값(서비스마다 `replicas: 1`, `100m` / `128Mi`, DB `db.t4g.micro`)으로 계산하고 그렇게 적는다. 종합 때 크기가 바뀌면 다시 계산한다.

## 가격

아는 공개 요금으로 추정하고 "대략"임을 밝힌다. 웹 검색이나 가격 도구가 있으면 현재 요금을 확인한다. 후보 사이의 자릿수 차이가 정확한 숫자보다 중요하다. 원화 환산은 환율 가정을 적는다.

## 정할 것

- 후보별 예상 월 비용(고정 / 변동 / 합계)과 예산 범위 대비 여유
- 비용을 줄일 여지: `replicas` 축소, 더 작은 DB, NAT 공유, 시연 뒤 `destroy`
