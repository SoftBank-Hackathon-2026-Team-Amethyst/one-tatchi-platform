# 보안 분석기

배포 전에 고칠 보안 문제와, 배포 대상 · 운영 관문에 영향을 주는 규제 요구를 찾는다.

## 조사할 것

- **레포 안의 비밀값.** 커밋된 `.env`, 소스에 박힌 키 · 비밀번호, 예시 파일에 남은 실제 값. 로컬 개발용 기본 비밀번호(compose의 `demo/demo` 등)는 운영에 쓰이지 않도록 표시만 한다. 파이프라인의 `secret-scan`(gitleaks)이 다시 검사한다.
- **의존성 취약점.** lockfile에 대해 생태계 도구를 돌린다(`pnpm audit`, `pip-audit`, `osv-scanner`, `trivy fs` 등). 도구가 없으면 설치하지 않고 "확인 못 한 것"에 적는다. 파이프라인의 `vuln-scan`(Trivy, HIGH 이상 차단)과 `image-scan`이 다시 검사한다.
- **이미지.** 베이스 이미지에 남는 패키지 매니저(npm · corepack · yarn · pip)는 취약점 검사 대상을 늘린다. 런타임 스테이지에서 지울 수 있는지 본다.
- **노출.** 밖에 열어야 하는 서비스와 안에만 있어야 하는 서비스. DB와 내부 API는 노출하지 않는다. FE가 BE를 프록시하면 Ingress는 FE만 켠다(`ingress.enabled`).
- **애플리케이션 설정.** CORS 범위, 디버그 모드, 인증 없는 관리 기능, 전송 구간 암호화.
- **규제.** 브리프의 `handles_sensitive_data`와 서비스 분석의 데이터 보관 위치 요구. 브리프가 `unknown`이면 `compliance`는 이미 `regulated`다. 분석 결과로 `none`을 제안하지 않는다.

## 정할 것

- **배포를 막는 문제**(비밀값 커밋, HIGH 이상 취약점, 인증 없는 관리 기능)와 **배포 뒤 고칠 문제**를 나눈다.
- 데이터 보관 위치 제한이 배포 대상을 제한하는지: 없음 / 데이터만 사내 / 전부 사내.
- 인프라가 제공해야 하는 설정: 저장 데이터 암호화, 접근 로그, 백업 보존. (AWS 모듈은 RDS 암호화 · 감사 로그 버킷을 기본으로 켠다.)
- `.trivyignore`에 넣을 예외가 있다면 CVE 번호와 근거(수정 버전 없음, 코드 경로상 미사용 등). 근거 없는 예외는 넣지 않는다.

## 결과 형식

`.deploy/analysis/security.md`

```md
# 보안 분석

## 배포를 막는 문제
## 배포 뒤 고칠 문제
## 노출
| 서비스 | 외부 노출 | 이유 |

## 규제
- 데이터 보관 위치 제한: 없음 | 데이터만 사내 | 전부 사내
- 인프라가 제공해야 하는 설정:
- 브리프 답변과 코드 발견의 불일치:

## 확인 못 한 것
## 가정
```

비밀값을 찾으면 값을 결과에 복사하지 않는다. 파일 경로와 줄 번호만 적는다.
