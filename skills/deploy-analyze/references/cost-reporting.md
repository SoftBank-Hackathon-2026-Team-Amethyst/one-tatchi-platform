# 비용 보고서 생성 계약 (T16 / C6)

예산 분석 표와 추천 후보 비용 요약은 같은 costs.json에서 생성한다. report 명령은 입력·단가·자원 평가와 계산 결과를 대조한 뒤 Markdown을 만든다. 가격을 다시 추정하거나 인터넷에 접속하지 않는다.

## 실행

```sh
python <skill-dir>/scripts/price.py report \
  --input <app-root>/.deploy/analysis/pricing-input.json \
  --prices <app-root>/.deploy/analysis/prices.json \
  --costs <app-root>/.deploy/analysis/costs.json \
  --assessment <app-root>/.deploy/analysis/resource-assessment.json \
  --candidate <candidate-id> \
  --budget-output <app-root>/.deploy/analysis/budget.md \
  --summary-output <app-root>/.deploy/analysis/cost-summary.md \
  --report <app-root>/.deploy/report.md
```

assessment는 C4로 생성한 입력에서 사용한다. candidate는 추천한 구성의 식별자이며 도구가 가장 싼 대상을 임의로 선택하지 않는다. 단가 조회 실패와 부분 소계만으로 배포 대상의 비용 우열을 확정하지 않는다.

표와 요약만 만들 때는 report 옵션을 생략한다. 대안 견적의 수치가 있으면 savings와 alternative-costs 옵션을 함께 전달한다. 두 견적의 해시와 비교 결과를 다시 확인하며 수치가 없으면 절감액 미산정 사유를 출력한다.

종료 코드는 전체 비용 자료와 제공한 비교가 완전하면 0, 비용 또는 비교에 미산정 항목이 있으면 3, 입력·연결·표지 오류면 2, 파일·내부 오류면 1이다. 가격 API 실조회나 전체 태스크 완료를 뜻하지 않는다. 환율·예산 미정은 보고서에 표시하며 USD 계산이 완전하면 생성 자체는 성공할 수 있다.

## 입력 확인

- C5 calculate로 같은 입력·단가·평가에서 다시 계산했을 때 기존 costs.json의 금액·판정·가정·연결 정보와 일치해야 한다. 생성 시각 자체는 서로 달라도 되지만 유효한 UTC 시각이어야 한다.
- 구성, 단가, 환율 또는 최종 추천 크기가 달라졌는데 이전 계산 결과를 넣으면 실패한다. map → lookup → calculate → report를 다시 실행한다.
- 일부 조회가 실패한 부분 결과는 그대로 표시한다. 공개 가격을 최신 조회값처럼 바꿔 끼우지 않는다.
- 보고서 생성 시각을 가격 조회 시각으로 표시하지 않는다. prices의 조회/시도 시각과 항목별 가격 적용 시점을 사용한다.

## 출력

budget.md에는 모든 후보의 구성 상태, 고정/변동 소계, 전체/증분, 원화, 예산 판정과 단가 조회 시각을 표시한다. 예산 경고·절감안, 미산정 항목과 실패 사유, SKU·단위·가격 적용 시점, 환율 근거와 가정, 원본 JSON 해시를 포함한다.

cost-summary.md에는 추천한 후보의 동일한 비용·경고·조회 시각·환율 근거와 미산정 조건을 표시한다. 입력·단가·계산 해시의 앞 12자리는 budget.md의 전체 해시와 연결된다.

- null은 미산정이며 0원으로 표시하지 않는다.
- 불완전한 금액은 확인된 소계와 추가 비용 미정으로 표시한다.
- 금액은 계산 결과의 십진 값으로 표시한다. 항목별 범위를 다시 더해 합계를 만들지 않는다.
- 원화 환율이 없으면 원화 환산과 예산 판정을 확정하지 않는다.
- 온프레미스 클라우드 0원과 별도 운영 비용을 구분한다. 운영 비용을 입력받았으면 평가 자료의 원화 범위를 별도 절에 표시하고 달러 비용에 섞지 않는다.
- 같은 견적을 비교하면 절감액은 0이며, 대안이 더 비싸면 절감액이 음수일 수 있다. 별도 대안이 없으면 검토 방향과 미산정 사유를 남긴다.

## 최종 보고서 갱신

최종 report.md에는 아래 표지 한 쌍을 둔다. 생성기는 이 구간만 교체하고 추천 이유·인프라·확장 계획·코드 수정·보안·기존 본문을 보존한다.

```md
## 추천
- 배포 대상: aws
- 이유: 앱과 운영 조건에 맞는 이유

<!-- pricing-summary:start -->
비용 도구가 생성한 후보 요약
<!-- pricing-summary:end -->

## 인프라 구성
기존 분석 결과
```

표지가 없거나 중복·역순이면 기존 보고서를 임의로 다시 작성하지 않고 실패한다. 이전 형식에 수동 예상 비용 문장이 있으면 분석 스킬이 기존 내용을 보존하면서 위 구간으로 옮긴 뒤 도구를 실행한다. 생성된 블록 밖에 다른 비용 추정 문장을 중복해서 적지 않는다.

출력은 서로 다른 Markdown 경로여야 한다. config.yaml·plan.yaml·brief.md와 입력 JSON을 덮어쓸 수 없다. report.md 전체 파일은 summary 출력으로 쓰지 않고 report 옵션으로 구간만 갱신한다. 심볼릭 링크 출력 경로는 거부한다.

모든 입력과 보고서 표지를 확인한 뒤 저장을 시작하고 파일별로 임시 작성·교체한다. 여러 Markdown 파일의 교체를 하나의 트랜잭션으로 보장하지는 않는다. 저장 실패는 성공으로 보고하지 않으며, 비용 근거 해시를 대조하고 같은 명령으로 다시 생성한다.

## 검증

자동 테스트는 합성 비용의 표·요약 일치, 예산 초과·부분 결과·환율 미정, 구성 변경 후 이전 결과 거부, 대안 비교 해시, 기존 보고서 본문과 config.yaml 보존을 확인한다. 실제 API와 demo-app의 전체 분석·리뷰 지점 1 검증은 C7에서 진행한다.
