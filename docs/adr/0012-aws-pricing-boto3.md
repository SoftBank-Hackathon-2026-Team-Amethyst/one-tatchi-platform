# [ADR-0012] AWS 가격 조회에 boto3 사용

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-10-09
* **관련:** T16 비용 추정 (예산 분석기), [이슈 #5](https://github.com/SoftBank-Hackathon-2026-Team-Amethyst/one-tatchi-platform/issues/5), C2 AWS 가격 조회와 응답 정규화 구현

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** 배포 전 비용 분석에 필요한 AWS 자원의 단가를 Price List Query API로 조회하려 한다. C1에서 Python 기반 `price.py` 진입점과 공통 입력·출력 JSON 계약을 정했다.
* **문제:** API 호출에는 인증과 요청 처리가 필요하다. 응답이 여러 페이지로 나뉘면 끝까지 조회해야 하며, 조회 결과에서 자원 조건에 맞는 가격을 선택하고 공통 JSON으로 변환해야 한다. 요청 계층을 직접 구현하면 가격 조회 외에도 인증 서명과 통신 처리를 유지해야 한다.
* **목표:** AWS 요청 계층의 구현 부담을 줄이고, 자원별 가격 필터링·응답 정규화·실패 처리에 집중한다. C1의 기존 인증 경로와 비밀값을 산출물에 기록하지 않는 계약을 유지한다.

## 2. 고려한 옵션들 (Considered Options)

### 1. Python boto3 사용

AWS SDK인 boto3의 Pricing 클라이언트로 서비스 속성과 상품 가격을 조회한다. SDK의 자격증명 탐색과 요청 인증을 사용하고, 응답을 C1의 `prices.json` 형식으로 변환하는 코드는 별도로 작성한다. [Pricing 클라이언트](https://docs.aws.amazon.com/boto3/latest/reference/services/pricing.html), [자격증명 처리](https://docs.aws.amazon.com/boto3/latest/guide/credentials.html)를 따른다.

**Pros**

* AWS 요청 인증과 자격증명 탐색을 SDK에 맡길 수 있다.
* Pricing API 호출 인터페이스를 활용해 상품 필터링과 응답 처리에 집중할 수 있다.
* SDK 클라이언트를 대체하는 테스트를 구성해 실제 네트워크 호출 없이 조회 처리 로직을 검증할 수 있다.

**Cons**

* boto3와 관련 의존성을 설치하고 관리해야 한다.
* SDK가 올바른 SKU 선택이나 공통 JSON 변환을 대신하지 않으므로 해당 로직은 직접 구현해야 한다.
* SDK의 오류를 그대로 노출하지 않고 C1의 오류 코드와 비밀값 없는 메시지로 변환해야 한다.

### 2. HTTP 요청과 인증 서명 직접 구현

AWS API에 보낼 HTTP 요청, 인증 서명, 자격증명 사용과 응답 처리를 직접 구현한다. 페이지 이동과 통신 실패 처리도 직접 관리한다.

**Pros**

* 요청 구성과 통신 동작을 세밀하게 통제할 수 있다.
* boto3 의존성 없이 필요한 API 호출 부분만 구현할 수 있다.

**Cons**

* 인증 서명과 자격증명 처리를 직접 구현하고 검증해야 한다.
* 페이지 이동, 통신 오류와 재시도 처리를 추가로 유지해야 한다.
* 가격 조회 기능과 별개인 요청 계층의 유지보수 범위가 커진다.

## 3. 결정 사항 (Decision Outcome)

* **Python boto3 사용을 선택한다.**
* **HTTP 직접 구현은 SDK로 충족할 수 없는 구체적인 요구가 생기면 재검토할 수 있는 대안으로 남긴다.**
* **현 단계에서는 자체 인증 서명과 HTTP 요청 계층을 구현하지 않는다.**

**이유**

* T16의 핵심은 조건에 맞는 가격을 조회하고 계산 근거를 남기는 것이다. 요청 인증을 직접 구현할 필요성이 현재 요구사항에 없다.
* 기존 SDK 자격증명 경로를 사용한다는 C1 결정과 일치한다.
* Python 기반 단일 CLI와 공통 JSON 계약을 유지하면서 AWS 조회 코드를 별도 모듈로 구성할 수 있다.

## 4. 결과

* C2에서 boto3 의존성과 AWS 조회 코드를 추가한다. 이 ADR은 구현 방식의 채택을 기록하며, 가격 조회 구현이나 실제 API 검증의 완료를 의미하지 않는다.
* Pricing API 접속 리전과 견적 대상 리전을 구분한다. 상품 조회 조건은 입력된 견적 대상 리전을 기준으로 구성한다.
* 조회 페이지를 끝까지 처리하고 자원 조건·가격 단위·구간 요금을 확인한다. 조건만으로 SKU를 확정할 수 없으면 임의로 첫 결과를 선택하지 않는다.
* 인증 실패, 권한 오류, 시간 초과 등은 [C1 가격 도구 계약](../../skills/deploy-analyze/references/price-format.md)의 부분 결과와 오류 형식으로 변환한다. 인증정보와 원본 SDK 예외 전체를 결과·로그에 기록하지 않는다.
* C2에서 응답 픽스처로 조회 처리를 검증하고, C7에서 실제 API 가격과 분석 보고서를 대조한다.
