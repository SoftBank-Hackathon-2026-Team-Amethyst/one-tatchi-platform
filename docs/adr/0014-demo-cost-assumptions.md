# [ADR-0014] 해커톤 데모의 월 비용 가정과 미산정 처리

* **상태 (Status):** 채택됨(Accepted)
* **날짜 (Date):** 2026-10-09
* **관련:** T16 비용 추정, [이슈 #5](https://github.com/SoftBank-Hackathon-2026-Team-Amethyst/one-tatchi-platform/issues/5), C7 검증·C8 마무리

## 1. 배경 및 문제 상황 (Context and Problem Statement)

* **상황:** demo-app은 해커톤 시연용 앱이다. 실제 API의 단가는 확보했지만 장기간의 운영 통계가 없어 트래픽·로그 등 월 사용량을 확정할 수 없다.
* **문제:** 실제 운영 통계를 기다리면 데모 비용 분석을 검증할 수 없다. 반대로 예상 사용량을 측정값처럼 표시하거나 무료 한도를 자동 적용하면 견적의 근거가 불분명해진다.
* **목표:** 설정에 근거한 기본 유지비와 명시적인 데모 사용량 가정으로 비용 표·예산 경고·절감안을 검증한다. 실제 청구액, 데모 예상액, 미산정 항목을 구분한다.

## 2. 고려한 옵션들 (Considered Options)

### 1. 명시적인 데모 월 사용량 가정으로 계산

확인한 자원 구성에 예상 사용량 범위를 입력한다. 보고서에 각 값의 출처와 가정을 남기고 계정 조건이 필요한 항목은 미산정으로 유지한다.

**Pros**
* 장기간 운용 없이도 가격 조회·계산·보고서·예산 경고를 검증할 수 있다.
* 같은 가정으로 기본 구성과 대안을 비교하고 재현할 수 있다.

**Cons**
* 예상액이며 실제 청구액을 보장하지 않는다.
* 계정 무료 구간·기존 사용량과 실제 클러스터 배치는 별도 확인이 필요하다.

### 2. 운영 통계를 모은 뒤 계산

서비스를 충분히 운용하고 사용량을 측정해 견적 입력을 만든다.

**Pros**
* 실제 앱의 사용 패턴과 데이터량을 반영한다.
* 사용량 가정을 줄일 수 있다.

**Cons**
* 짧은 해커톤 시연만으로 월 사용량을 검증하기 어렵다.
* T16 구현 검증을 위해 장기간 운용과 비용 지출을 추가로 요구하게 된다.

### 3. 미정 항목을 모두 제외하거나 0원으로 처리

알려진 고정비만 전체 비용처럼 표시한다.

**Pros**
* 계산과 표시가 단순하다.

**Cons**
* 실제 발생할 수 있는 비용을 누락해 예산 충족을 잘못 판단할 수 있다.
* 미지원·미조회·미사용과 실제 0원을 구분하지 못한다.

## 3. 결정 사항 (Decision Outcome)

* **명시적인 데모 월 사용량 가정으로 계산하는 옵션을 선택한다.**
* **운영 통계 기반 보정은 향후 확장으로 남긴다.**
* **미정 비용을 0원으로 대체하는 옵션은 채택하지 않는다.**

**이유**
* 현재 목적은 해커톤 비용 분석 시연이며 실제 장기 운영비 예측 모델을 검증하는 작업이 아니다.
* API 단가·사용량 가정·가격 조회 시각·계산 결과를 분리하면 완료 기준을 재현할 수 있다.
* 단일 AWS/GCP/온프레미스 후보 비교와 기존 부분 결과 계약을 유지한다.

## 4. 결과

### 기본 구성과 예상 사용량

* 월 유지 시간은 730시간, 트래픽 계획은 30일이다. 시연 몇 분의 요금이 아닌 한 달 동안 구성을 유지하는 예상액이다.
* 사용자 상한은 하루 100명, 평균 체류는 5분이다. 앱의 1초·3초·3초 폴링을 기준으로 월 약 150만 API 요청을 가정한다. 실측 처리 성능을 주장하지 않는다.
* 월 인터넷 송신과 NAT 처리량은 각각 5~10 GB, 로그 수집은 2~5 GB, 평균 로그 저장/추가 보존량은 1~2 GB-month로 가정한다. GCP는 동일 바이트량을 GiB 단위로 변환한다. 추가 보존은 실제 보존 설정이 확인된 값이 아니라 조건부 비용을 보여 주는 가정이다.
* 이미지 저장은 저장소당 0.5~1 GB-month, 시크릿은 AWS 2개/GCP 활성 버전 1개의 한 달 사용, 접근은 자원당 월 1만 회로 가정한다.
* AWS 공인 IPv4는 ALB 3개×2개 AZ와 NAT 1개를 기준으로 7개를 한 달 유지한다고 가정한다. 실제 동적 주소 개수·시간을 측정한 값이 아니다. ALB 평균 LCU는 대당 0.05~0.1, 월 36.5~73 LCU-hours로 가정한다.
* AWS 공유 감사 S3는 1~2 GB-month와 월 쓰기 1천 회·읽기 1천 회로 가정한다. 외부 DNS·백업·추가 네트워크 텔레메트리 등 이 자원 목록 밖 비용은 별도 확인 범위로 표시한다.
* GCP 노드 디스크는 대당 30 GiB-month, SQL 디스크는 20 GiB-month의 유지 시나리오를 사용한다. 모듈의 초기 크기에 맞춘 비용 가정이며 실제 청구량·자동 증설 검증은 아니다.
* GCP Public NAT는 VM 3대의 730시간 할당, NAT IP는 1개의 730시간 사용으로 가정한다. 로드밸런서는 두 공개 환경을 730시간 유지하는 구성을 가정하며 실제 런타임과 같다고 주장하지 않는다.
* GCP Prometheus는 100개 시계열을 15초마다 수집해 월 17,520,000개 샘플로 가정한다. 인터넷 송신·메트릭의 계정 기존 사용량은 미정으로 남긴다.
* AWS 유료 커스텀 메트릭은 이번 데모 견적 범위에서 제외한다. 자체 Prometheus의 노드·디스크 비용은 포함한다. 이 제외는 계정에 유료 커스텀 메트릭이 없다는 확인이 아니다.

### 비교와 남은 미산정

* 기본 예산은 T15의 월 0~100,000원 범위다. 환율은 별도 입력의 기준일·출처를 보존한다.
* 기본 비교는 전체 구성 비용이다. 앱을 새로 추가한 증분 비용은 이번 시나리오의 입력이 없어 미산정으로 남긴다.
* GCP 이미지 저장소·로그·시크릿의 무료 구간 자격과 계정/프로젝트 기존 사용량은 추측하지 않는다. 이 항목과 계정 구간 비용은 미산정으로 남기며 AWS/GCP의 비용 우열을 확정하지 않는다.
* 온프레미스의 클라우드 요금 0원과 전기·장비·인건비 미산정을 함께 표시한다.
* 수용량의 합계 검사는 앱 BE 100m/128Mi, FE 50m/32Mi, 환경별 replicas 1과 Blue-Green 배수 2를 사용한다. 노드당 CPU 1900m·메모리 3072Mi, AWS 파드 슬롯 17, 전체 예약 CPU 1000m·메모리 2048Mi·파드 25개를 데모 가정으로 입력한다. 실제 배치·allocatable·성능을 검증한 값이 아니며 자원 증설 여부를 확정하지 않는다.

### 절감 대안과 가격 근거 재사용

* 절감 대안은 노드 3대와 DB를 유지하고, 데모의 외부 공개 환경을 하나로 줄여 ALB를 3개에서 2개, 공인 IPv4 가정을 7개에서 5개로 줄이는 비교 시나리오다. 같은 월 트래픽을 유지하고 ALB별 LCU 사용량을 재배분한다.
* 이 대안은 공개 접근 범위가 달라진다. 실제 배포·삭제를 실행하거나 운영 가용성·규제 조건을 충족했다고 주장하지 않는다. 적용 전 확인 사항을 보고서에 함께 표시한다.
* 사용량·수량만 달라지는 시나리오는 `reuse-prices`로 기존 실제 API 가격표를 검증하여 재사용한다. 원본 입력·가격 해시, 대상·리전·자원·SKU 선택 조건·단위를 대조하고 재사용 근거 JSON을 별도로 남긴다. SKU·규격·리전·단위가 달라지면 새 lookup이 필요하다.
* 재사용은 새 API 조회가 아니다. 원본 조회 시각·적용일·Money·구간을 그대로 보존하며 재사용 시각을 조회 시각으로 바꾸지 않는다.
* 완료 근거는 [데모 검증 기록](../validation/T16-demo-completion.md)에 남긴다. 실제 측정값과 데모 가정을 섞지 않는다.
